# WaSaLei Backend API Docs

Base URL:

```text
http://127.0.0.1:5000
```

Common response shape:

```json
{
  "success": true,
  "status": "success"
}
```

Error response shape:

```json
{
  "success": false,
  "status": "error",
  "message": "error message"
}
```

ID list fields such as `season_ids`, `color_ids`, and `style_ids` accept:

```json
[1, 2, 3]
```

```json
"1,2,3"
```

```json
1
```

---

## Health

### GET `/`

Checks whether the backend is running.

Response:

```json
{
  "status": "ok",
  "success": true
}
```

## Static Images

### GET `/pictures/<path:filename>`

Serves files from the project-level `pictures` directory.

Examples:

```text
GET /pictures/input/input.jpg
GET /pictures/output/output.png
GET /pictures/final/abc123.png
```

### GET `/images/<path:filename>`

Serves image files from `pictures/output`.

Example:

```text
GET /images/output.png
```

## Auth APIs

### POST `/api/auth/register`

Request:

```json
{
  "name": "測試",
  "account": "test@example.com",
  "password": "123456"
}
```

Success: `201`

```json
{
  "success": true,
  "status": "success",
  "message": "註冊成功"
}
```

Request:

```json
{
  "account": "test@example.com",
```

```json
  "status": "success",
```

## Space APIs

### GET `/api/space/predefined`

Returns supported space types.

```json
{
  "status": "success",
  "success": true,
  "data": ["衣櫃", "行李箱"]
}
```

### POST `/api/space`

Creates a storage space.

Request:

```json
{
  "user_id": 1,
  "space_type": "衣櫃",
  "capacity": 20
}
```

### GET `/api/space/user/<user_id>`

Gets all spaces for a user.

Optional query:

```text
?type=衣櫃
```

### GET `/api/space/<space_id>/items`

Gets all items in one space.

Example:

```text
GET /api/space/1/items
```

Response:

```json
{
  "status": "success",
  "success": true,
  "data": [
    {
      "item_id": 1,
      "name": "純白短袖T恤",
      "type": "上衣",
      "seasons": ["春季", "夏季"],
      "styles": ["休閒"],
      "colors": ["白色"],
      "color1": "白色",
      "color2": null,
      "color3": null,
      "photo_url": null
    }
  ]
}
```

Empty spaces return success with an empty array:

```json
{
  "status": "success",
  "success": true,
  "data": []
}
```


### GET `/api/space/<space_id>/capacity`

Gets capacity status for one storage space.

Example:

```text
GET /api/space/1/capacity
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "data": {
    "Space_ID": 1,
    "Space_Type": "??",
    "Space_Name": "????",
    "User_ID": 1,
    "Capacity": 20,
    "Used_Capacity": 8,
    "Remaining_Capacity": 12,
    "Is_Full": 0
  }
}
```

Not found: `404`

### PATCH `/api/space/<space_id>/capacity`

Updates the capacity of one storage space.

Request:

```json
{
  "capacity": 30
}
```

Rules:

- `capacity` must be a positive integer.
- `capacity` cannot be smaller than the current used item count.

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "message": "????????"
}
```

### DELETE `/api/space/<space_id>`

Deletes one storage space.

Example:

```text
DELETE /api/space/1
```

Behavior:

- The `item.Space_ID` foreign key uses `ON DELETE SET NULL`.
- Items originally in this space are kept, but no longer belong to any space.

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "message": "???????????????????????????"
}
```

Not found: `404`

## Item APIs

### GET `/api/items/<item_id>`

Gets one item detail, including type and many-to-many attributes.

Example:

```text
GET /api/items/1
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "data": {
    "item_id": 1,
    "name": "純白短袖T恤",
    "notes": "容易髒要注意",
    "photo": null,
    "photo_url": null,
    "user_id": 1,
    "space_id": 1,
    "type_id": 1,
    "type": "上衣",
    "season_ids": [1, 2],
    "seasons": ["春季", "夏季"],
    "style_ids": [1],
    "styles": ["休閒"],
    "color_ids": [1],
    "colors": ["白色"]
  }
}
```

Not found: `404`

### PATCH `/api/items/<item_id>`

Updates item basic fields and many-to-many attributes.

Request can include any subset of these fields:

```json
{
  "name": "黑色外套",
  "notes": "冬天穿",
  "space_id": 1,
  "type_id": 3,
  "season_ids": [3, 4],
  "color_ids": [3],
  "style_ids": [1, 2]
}
```

Behavior:

- Omitted fields are not changed.
- If `season_ids`, `color_ids`, or `style_ids` are included, the old mappings are replaced.
- Passing an empty array clears that mapping group.

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "data": {
    "item_id": 1,
    "name": "黑色外套"
  }
}
```

### DELETE `/api/items/<item_id>`

Deletes one item.

Example:

```text
DELETE /api/items/1
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "message": "刪除衣服成功"
}
```

Not found: `404`



### GET `/api/items/<item_id>/outfits`

Gets outfit history records related to one item.

This endpoint uses only the existing tables:

```text
history_outfit -> history
```

There is no `outfit` table in this project.

Example:

```text
GET /api/items/1/outfits
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "data": [
    {
      "imageUrl": "/uploads/history_work_meeting.jpg",
      "wornDate": "2026-05-01",
      "occasion": "上班會議"
    }
  ]
}
```

Empty result:

```json
{
  "success": true,
  "status": "success",
  "data": []
}
```
### PATCH `/api/items/<item_id>/space`

Moves one item to another storage space.

Request:

```json
{
  "space_id": 2
}
```

Rules:

- `space_id` is required.
- The target space must exist.
- The target space must not be full.

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "message": "??????"
}
```

Error: `400`

```json
{
  "success": false,
  "status": "error",
  "message": "???????????????"
}
```

### POST `/api/items/preview-image`

Backward-compatible one-step image preview API.

Content type:

```text
multipart/form-data
```

Fields:

- `file` or `image`: image file
- `mode`: optional, default `garment`

Flow:

```text
upload image -> save to pictures/input -> parse -> write pictures/output/output.png
```

### POST `/api/items/confirm-image`

Confirms `pictures/output/output.png` as the final item image and creates the item record.

Request:

```json
{
  "user_id": 1,
  "name": "白色襯衫",
  "space_id": 1,
  "type_id": 1,
  "season_ids": [1, 2],
  "color_ids": [1],
  "style_ids": [1]
}
```

Flow:

```text
copy pictures/output/output.png to pictures/final/<uuid>.png
-> insert item
-> insert item_season / item_color / item_style mappings
-> clear pictures/input and pictures/output
```

## Outfit / History APIs

Outfit history dates use `wornDate` in `YYYY-MM-DD` format. The database column is `history.Worn_Date`.

### GET `/api/outfits/occasion-options`

Returns occasion options for the outfit filter dropdown.

Query:

```text
?user_id=1
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "data": ["all", "上班會議", "週末咖啡廳"]
}
```

### GET `/api/outfits`

Gets all outfit history records for one user.

Query:

```text
?user_id=1
?user_id=1&occasion=上班會議
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "data": [
    {
      "id": 1,
      "wornDate": "2026-05-01",
      "photo": "/uploads/history_work_meeting.jpg",
      "note": "正式但不要太沉重。",
      "occasion": "上班會議",
      "item_ids": [1, 9, 10]
    }
  ]
}
```

### GET `/api/outfits/<history_id>`

Gets one outfit history record with item details.

Example:

```text
GET /api/outfits/1
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "data": {
    "id": 1,
    "wornDate": "2026-05-01",
    "photo": "/uploads/history_work_meeting.jpg",
    "note": "正式但不要太沉重。",
    "occasion": "上班會議",
    "items": [
      {
        "id": 1,
        "name": "白色棉質長袖襯衫",
        "color": ["白色", "none", "none"],
        "season": ["春", "秋"],
        "type": "上身長",
        "style": ["正式", "日常"],
        "imageUrl": "/uploads/demo_white_shirt.jpg"
      }
    ]
  }
}
```

Not found: `404`

### POST `/api/outfits`

Creates one outfit history record and attaches selected item ids.

Request:

```json
{
  "user_id": 1,
  "occasion": "上班會議",
  "photo": "uploads/history_work_meeting.jpg",
  "note": "正式但不要太沉重。",
  "wornDate": "2026-05-01",
  "item_ids": [1, 9, 10]
}
```

Success: `201`

### PATCH `/api/outfits/<history_id>`

Updates one outfit history record. Omitted fields are not changed.
If `item_ids` is included, old outfit item mappings are replaced.

Request:

```json
{
  "occasion": "週末咖啡廳",
  "note": "舒適日常穿搭。",
  "wornDate": "2026-05-02",
  "item_ids": [2, 3, 6]
}
```

Success: `200`

### DELETE `/api/outfits/<history_id>`

Deletes one outfit history record. Rows in `history_outfit` are removed by cascade.

Example:

```text
DELETE /api/outfits/1
```

Success: `200`

```json
{
  "success": true,
  "status": "success",
  "message": "刪除穿搭紀錄成功"
}
```

## Search API

### GET or POST `/api/search`

Searches wardrobe items by user and optional filters.

GET example:

```text
GET /api/search?user_id=1&keyword=黑&space_id=1&season_ids=1,2
```

POST example:

```json
{
  "user_id": 1,
  "keyword": "黑",
  "space_id": 1,
  "type_id": 3,
  "season_ids": [3, 4],
  "color_ids": [3],
  "style_ids": [1]
}
```

Filter behavior:

- Different groups are combined with `AND`.
- Multiple ids inside the same group use `IN (...)`, so they behave like `OR`.

## Image Pipeline APIs

Recommended frontend flow:

```text
POST /api/images/upload-input
-> POST /api/images/parse-input
-> display preview_url
-> POST /api/items/confirm-image
```

### POST `/api/images/upload-input`

Uploads the current input image.

Content type:

```text
multipart/form-data
```

Fields:

- `file` or `image`: image file

### POST `/api/images/parse-input`

Parses the current image in `pictures/input`.

Request:

```json
{
  "mode": "garment"
}
```

Response includes:

```json
{
  "input_path": "pictures/input/input.jpg",
  "preview_path": "pictures/output/output.png",
  "preview_url": "/pictures/output/output.png",
  "colors": []
}
```

## Capacity Notes

Capacity is managed by counting current items in each space instead of trusting a manually maintained number.

Recommended behavior:

- New spaces start with `Used_Capacity = 0`.
- Capacity status uses `COUNT(Item_ID)` to calculate `Used_Capacity`.
- Creating an item should check whether the target space is full.
- Moving an item should check whether the target space is full.
- Deleting a space keeps its items, but sets their `Space_ID` to `NULL` through the database foreign key.
